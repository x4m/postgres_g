# Прототип внутристраничного индексирования в памяти

Дата: 2026-08-03. Машина g2. База — `REL_18_0`, прототип накладывается скриптом
`bench/scripts/apply_intrapage.py` (294 строки в трёх файлах).

## Что сделано

Элементы **внутренней** страницы разбиваются на группы примерно по $\sqrt{f}$,
для группы считается `union` её ключей и хранится как синтетический индексный
кортеж. При просмотре страницы `consistent` сначала вызывается для ключа
группы; ложный ответ пропускает всю группу.

Структура живёт в локальной для процесса хеш-таблице, ключ —
`RelFileLocator` и номер блока, актуальность проверяется по LSN страницы.
Строится не раньше третьего обращения к странице (параметр
`gist_page_skip_threshold`). Включается параметром `gist_page_skip`, по
умолчанию выключено.

**Формат индексного кортежа, журнал и восстановление не затронуты** — это и
было целью, поскольку именно на них остановился вариант 2019 года.

## Корректность

3000 оконных запросов к 2 млн точек, суммарное число найденных строк:

| режим | строк | запросов |
|---|---|---|
| выключено | 96 229 | 3 000 |
| включено | 96 229 | 3 000 |
| включено, повтор | 96 229 | 3 000 |

Совпадает точно. Это ожидаемо и следует из инварианта GiST: ключ, покрывающий
ключи группы, ведёт себя как ключ внутреннего узла, а `consistent` для
внутреннего ключа не возвращает ложь, если хоть один элемент поддерева
подходит. Пропуск по ложному ответу результатов не теряет.

## Выигрыш

Соединение по индексу: 200 тыс. внешних строк, селективное окно, индекс и
таблица в буферном кэше.

| режим | прогон 1 | прогон 2 | прогон 3 |
|---|---|---|---|
| выключено | 2,23 с | 2,23 с | 2,23 с |
| включено | 1,67 с | 1,68 с | 1,69 с |

**25 % быстрее**, разброс в пределах 0,01 с. Оценка сверху по профилю давала
28 %, то есть прототип забирает почти весь предсказанный запас.

## Отсутствие ухудшения там, где выигрыша быть не должно

Неселективные запросы (в ответе тысячи строк, работа смещена на листовой
уровень, где структура не строится):

| режим | прогон 1 | прогон 2 |
|---|---|---|
| выключено | 0,85 с | 0,85 с |
| включено | 0,87 с | 0,85 с |

Различие в пределах шума.

Порог построения: при пороге 1000 структура не строится вовсе, при пороге 1 —
сразу. На короткой нагрузке (20 тыс. внешних строк) 0,22 с против 0,19 с, то
есть построение окупается даже при немедленном включении. Порог по умолчанию
взят из осторожности, а не по необходимости.

## Что осталось проверить

- Класс операторов с дорогим `union`: там построение может не окупиться.
  Проверять на `poly_ops` или на сигнатурных классах.
- Многоколоночные индексы: прототип не проверялся на них.
- Поведение при конкурентных изменениях страницы: проверка по LSN написана, но
  не испытана нагрузкой с одновременными вставками.
- Нежурналируемые и временные отношения: LSN там не меняется при модификации,
  структура может устареть незаметно. Сейчас это не обработано и является
  дефектом прототипа.
- Память при большом числе горячих страниц; вытеснение сейчас грубое — при
  переполнении кэш сбрасывается целиком.

## Оценка

Направление подтвердилось: 25 % на профильной нагрузке при точном совпадении
результатов и без изменений формата, журнала и восстановления. Возражение,
из-за которого не прошёл вариант 2019 года, снято по построению, а не
оговорками.

До предложения в список рассылки нужно закрыть пункты выше, прежде всего
нежурналируемые отношения и многоколоночные индексы.
