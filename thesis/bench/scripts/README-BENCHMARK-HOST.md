# Общий бенчмарк-хост: протокол и что нельзя удалять

Этот файл копируется на машину как `/home/x4mmm/README-BENCHMARK-HOST.md` и
`/mnt/nvme/data/README-DO-NOT-DELETE.md`. Машину делят несколько агентов,
работающих под одной учётной записью.

## Замок

Перед любой тяжёлой работой — сборкой, замером, массовой загрузкой,
CREATE INDEX, REINDEX, VACUUM, pgbench:

```sh
exec 9>/home/x4mmm/benchmark.lock
flock -n 9 || { echo "benchmark host is busy"; exit 75; }
```

Замок **один на машину**, а не на задачу: мешают друг другу не задачи, а
нагрузка на процессор и диск. Долгоживущие процессы не должны наследовать
дескриптор — запускать с `9>&-`:

```sh
pg_ctl ... 9>&-
psql ... 9>&-
make ... 9>&-
```

Замок держится на всю серию: сборка, запуск и остановка сервера, прогрев, все
варианты и повторы. Перед серией — `uptime` и `ps -eo pid,pcpu,pmem,args
--sort=-pcpu | head -20`; при посторонней нагрузке не начинать. После серии
повторить; если во время серии появилась посторонняя нагрузка, серию считать
недействительной.

Если замок занят — не обходить и не ждать молча: сообщить владельцу задачи и
заняться локальной работой.

Готовый модуль: `~/benchlock.sh` (`bench_lock`, `bench_preflight`,
`bench_postflight`).

## Свои каталоги, порты, имена

Каждый агент использует собственные `~/bench-<задача>/` и датадиры. **Нельзя
останавливать, переиспользовать или изменять чужие кластеры.** После работы
штатно остановить только свой.

## Что в /mnt/nvme/data нельзя удалять

Каталоги ниже относятся к работе над диссертацией по GiST (P1–P7). Некоторые
воспроизводятся скриптами за минуты, некоторые — за часы. **Перед удалением
чего-либо в `/mnt/nvme/data` спросите владельца задачи.** Место на диске при
необходимости расширяется, это дешевле, чем пересобирать данные.

| каталог | к чему относится | пересоздание |
|---|---|---|
| `picksplit`, `naive` (53 ГБ) | P1, сравнение построения вставкой и `picksplit` на 10⁷ точках | часы |
| `k` | P1, развёртка по размеру буфера сортированного построения | часы |
| `ip-base`, `ip-skip` | внутристраничное индексирование, замеры соединения и вставки | часы |
| `skip` | то же, ранняя редакция | часы |
| `ginlock` | P2, блокировки при сборке мусора в дереве вхождений | ~30 мин |
| `dim` | P7, зависимость перекрытия от размерности | ~25 мин |
| `amchk`, `amcost`, `lb`, `la` | P3, полнота и стоимость проверки инвариантов | ~10 мин |

Сборки в `~/bench-*` пересобираются из `~/pgsrc` скриптами
`build_*.sh`; старые версии (2017–2019) собираются не всякой glibc и требуют
обходов, записанных в самих скриптах, — восстанавливать их дороже, чем кажется.

## Прочее

- Не оставлять работающими ненужные серверы: они занимают память и искажают
  чужие замеры.
- `sudo` есть; сброс страничного кэша и изменение `read_ahead_kb` используются
  в замерах ввода-вывода.
