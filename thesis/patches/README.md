# Патчи

## `0001-gist-intrapage-skip-prototype.patch`

Прототип внутристраничного индексирования в памяти. База — `REL_18_0`,
294 строки в трёх файлах. Устройство — `../plan/90-intrapage-design.md`,
измерения — `../bench/results/2026-08-03-intrapage-prototype.md`.

Применить:

```sh
cd ~/pgsrc && git checkout -qf REL_18_0 && git clean -qfdx
git apply .../0001-gist-intrapage-skip-prototype.patch
```

Либо наложить скриптом `../bench/scripts/apply_intrapage.py`, который делает то
же самое правками по якорям и потому переносится между базовыми версиями.

Включение: `SET gist_page_skip = on` (по умолчанию выключено),
`gist_page_skip_threshold` — с какого по счёту обращения к странице строить
структуру.

### Состояние: устройство отвергнуто, оставлено как запись

Хранение структуры вне страниц индекса признано нежизнеспособным: это
дублирование производных данных мимо менеджера буферов, без учёта памяти и без
согласования с вытеснением страниц. Патч сохранён как запись о проверенном —
он работает и даёт 25 % на соединении по индексу, но предлагать его не следует.

Рабочее направление — пропускающие кортежи **на странице**, как в патче 2018
года (тред `[WiP] GiST intrapage indexing`). Идеи к нему —
`../plan/91-skipgroups-ideas.md`.

### Прочие замечания к прототипу

Комментарии в коде на русском — их нужно перевести. Помимо этого:

**Известный дефект.** Нежурналируемые и временные отношения: LSN страницы там
не меняется при модификации, поэтому построенная структура устареет незаметно и
запрос вернёт неверный результат. Нужна проверка на журналируемость при входе в
`gist_skip_lookup`.

**Не проверено:**

- многоколоночные индексы;
- классы операторов с дорогим `union` — там построение может не окупиться;
- конкурентные изменения страницы: проверка по LSN написана, но нагрузкой с
  одновременными вставками не испытана;
- взаимодействие с `gistkillitems`: пометки LP\_DEAD меняют страницу, но
  ключ группы при этом остаётся верным (консервативно шире), — рассуждение
  есть, проверки нет.

**Спорное по устройству, что спросят в рассылке:**

- кэш локален для процесса и не учитывается ни в каком лимите памяти;
- вытеснение грубое: при переполнении сбрасывается целиком;
- структура переживает вытеснение самой страницы из буферного кэша;
- размер группы жёстко $\sqrt{f}$, без обоснования оптимальности.
