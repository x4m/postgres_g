Headline patch · July 9 · commit 86ab7f4c721

JSON_TABLE PLAN: a four-year saga

+2,017 / −112 lines · 13 files · 7 co-authors · 11 reviewers · discussion dating to 2022

Alexander Korotkov

If July has one flagship patch, this is it. JSON_TABLE arrived in PostgreSQL 17 without the PLAN clause, and the debt to the SQL/JSON standard has been outstanding ever since.

What PLAN solves. JSON_TABLE unrolls nested paths through NESTED PATH. The question is how to join rows coming from several of them. Until July the answer was hardcoded — parent to child via LEFT OUTER, sibling to sibling via UNION. Now you choose.

              ┌──────────────────────────────┐
              │  row pattern  '$'  AS root   │
              └──────────────┬───────────────┘
                             │ INNER / OUTER  ← parent↔child
             ┌───────────────┴────────────────┐
  ┌──────────▼──────────┐         ┌──────────▼──────────┐
  │ NESTED '$.phones'   │  UNION  │ NESTED '$.emails'   │
  │        AS ph        │◄───────►│        AS em        │
  └─────────────────────┘  CROSS  └─────────────────────┘
                             ▲
       siblings: UNION (one row per sibling) ─┘
                 or CROSS (cartesian product)
[ PLAN ( json_table_plan )
| PLAN DEFAULT ( { INNER | OUTER } [ , { CROSS | UNION } ]
               | { CROSS | UNION } [ , { INNER | OUTER } ] ) ]

Departing from the standard. SQL/JSON requires that when a PLAN is present, every NESTED PATH carry an explicit AS name. PostgreSQL decided otherwise — unnamed paths get a generated name. But that generated name has a price:

-- works: PLAN DEFAULT with an unnamed NESTED path
SELECT * FROM JSON_TABLE(
    jsonb '[]', '$' AS path1
    COLUMNS ( NESTED PATH '$' COLUMNS ( foo int PATH '$' ) )
    PLAN DEFAULT (UNION)
) jt;

-- fails: an explicit PLAN() refers to paths by name,
-- and a generated name cannot be spelled out
SELECT * FROM JSON_TABLE(
    jsonb '[]', '$' AS path1
    COLUMNS ( NESTED PATH '$' COLUMNS ( foo int PATH '$' ) )
    PLAN (path1)
) jt;
ERROR:  nested path not covered by the plan

The landing. Big patches never land clean. Within two weeks: a forgotten catversion bump; a revert of cascading ON ERROR; parentheses lost when deparsing nested joins; generated path names colliding; documentation fixes; removal of redundant re-evaluation of nested paths; an unreachable error check deleted. Twelve commits in July carry “JSON” in the subject — the classic descent curve of a large feature.

Second page · July 2 · commit a5918fddf10

Replication conflicts, now in a table

+1,451 / −40 lines · 31 files

Amit Kapila

Until now a logical replication conflict went to postgresql.log as plain text. Want to analyse it? Parse logs with regexes. Conflicts can now be written to a table instead.

CREATE SUBSCRIPTION sub
  CONNECTION 'host=pub dbname=app' PUBLICATION pub
  WITH (conflict_log_destination = 'table');
  --  'log' | 'table' | 'all'
   apply worker
        │  conflict detected
        ▼  (insert_exists / update_origin_differs / …)
  ┌────────────────────────────┐
  │  conflict_log_destination  │
  └──────┬──────────────┬──────┘
     'log'│              │'table'
         ▼              ▼
  postgresql.log   pg_conflict schema (system-managed)
                   └── pg_conflict_log_<subid>
                         ▲ internal dependency
                   DROP SUBSCRIPTION → table disappears

The log schema, straight from ConflictLogSchema[]:

{"relid",OID} {"schemaname",TEXT} {"relname",TEXT}
{"conflict_type",TEXT} {"remote_xid",XID}
{"remote_commit_lsn",LSN} {"remote_commit_ts",TIMESTAMPTZ}
{"remote_origin",TEXT} {"replica_identity_full",BOOL}
{"replica_identity",JSON} {"remote_tuple",JSON}
{"local_conflicts",JSONARRAY}

Note: json, not jsonb. The code comment states the reason outright — this is an exact audit snapshot, and jsonb would normalize it: reorder keys, collapse duplicates, lose number formatting. Nobody intends to search by tuple; the scalar columns get indexed, while the json fields are payload to inspect after the fact.

The table is locked down. Forbidden: ALTER, DROP, CREATE INDEX, triggers, rules, policies, extended statistics, use as an inheritance parent or foreign-key target, and manual INSERT, UPDATE, MERGE or row locking. Exactly two operations remain — DELETE and TRUNCATE, so old rows can be pruned.

Conflict tables are also excluded from publications, including FOR ALL TABLES. Otherwise: a cheerful infinite loop.

GROUP BY ALL

2026 — 2026
survived one cycle

Commit a32733d8f10, Tom Lane, July 17. The feature that let you write GROUP BY ALL instead of spelling out every non-aggregate expression has been reverted — and out of branch 19 as well (Backpatch-through: 19).

ef38a4d9756  "Add GROUP BY ALL"            ← life
2ce745836    "comment improvements"
    …
a32733d8f10  Revert "Add GROUP BY ALL"     ← death

The reason, from the commit message: post-commit review found it missed the special handling for entries that also appear in ORDER BY. The query returned wrong results when ORDER BY specified non-default equality semantics.

Fixable with refactoring — but “too much code churn for late beta”. The classic PostgreSQL calculus: wrong results plus late beta equals revert, no debate.

Reported by Chao Li. The promise — “We'll revert and try again in v20” — is on the table. One line up in the July log sits Update GROUP BY ALL comments about window functions, committed on July 8, nine days before the funeral.

The great cleanup

July took out the trash

Goodbye to everything older than v10. Four commits from Nathan Bossart on July 2 removed support for pre-v10 servers from pg_dump/pg_dumpall, pg_upgrade and psql. Late in the month, from AdjustUpgrade.pm too.

Old-server support in pg_dump/pg_upgrade/psql:

2021, for v15:  9.2 ─────────────────────────► 15
2026, for v20:                  10 ──────────► 20
                                ▲ new floor

Project policy is to support at least 10 prior major versions. The floor was last raised in 2021. pg_restore's ability to read old archives is untouched — though, as the commit honestly notes, it is “fair to wonder how that might be tested nowadays”.

refint, forty years on. Sample code from the pre-FOREIGN KEY era, deleted after six consecutive fix commits. The verdict: “the code has more issues than its sample-code value justifies”.

The toolchain floor rises. Visual Studio 2022 minimum — VS 2019 nominally supports _Generic but is, quoting the commit, “just broken for that”. ICU 55 minimum, since RHEL 7 is no longer supported. A requirement for Tcl 8.6 lasted less than a day before being reverted.

Other casualties: pg_spin_delay(), RADIUS among initdb's auth methods, the SQL function getpgusername(), WaitEventCustomCounterData, a “sketchy” TerminateThread() call on Ctrl-C under Windows, and the apparent support for SECURITY LABEL ON PROPERTY GRAPH that never actually existed.

The planner

The missing switch

e01b23b84e4, Richard Guo, July 9. We have had enable_hashagg for twenty years, but no symmetric knob for sorted grouping.

SET enable_groupagg = off;   -- on by default

It covers GroupAggregate, Group, the sort-based Unique step used for DISTINCT and semijoin unique-ification, and the sorted mode of SetOp. Not a hard switch — it only bumps disabled_nodes.

A side effect worth noting: several tests had been turning off enable_sort purely to force a hashed plan. They now say enable_groupagg instead. In union.sql that finally opened a path to testing hashed UNION, which had been unreachable before.

Hash Join meets NULL

60826a352d4, David Rowley, July 31. A three-commit detective story. adf97c156 taught expression evaluation to hash; 9ca67658d fixed memory stomping there — and left a gap.

key ──► EEOP_HASHDATUM_FIRST_STRICT ──► interim hash
             │ key = NULL → jump to jumpdone
             ▼
       ┌─────────────┐
       │  jumpdone   │ expects: resnull / resvalue
       └─────────────┘ reality:  NOT SET ✗
             ▼
   rows enter the hash table that can never
   match a join partner

Not a wrong answer — just burnt CPU and memory. Hash Agg and hashed subplans were unaffected: neither uses the STRICT steps.

Elsewhere in the optimizer: a better row-count estimate for UNION; stadistinct now propagates through GROUP BY/DISTINCT in subqueries and CTEs; a trilogy on nullingrels; a pruning fix for RANGE DEFAULT partitions; nullability and strictness for ScalarArrayOpExpr.

Statistics · Michael Paquier's month

Locks, per backend

Of Paquier's 39 commits the lion's share concern pgstat. Twenty-five commits in July touch statistics one way or another.

8c579bdc366 (authored by Bertrand Drouvot). There was pg_stat_lock, cluster-wide. Now there is a per-backend view too:

SELECT a.pid, a.state, l.locktype, l.waits,
       l.wait_time, l.fastpath_exceeded
FROM   pg_stat_activity a
CROSS JOIN LATERAL pg_stat_get_backend_lock(a.pid) l
WHERE  l.waits > 0
ORDER BY l.wait_time DESC;

fastpath_exceeded counts how often a backend spilled past fast-path locking. In the same month Paquier added an entire new documentation section on fast-path locking. Read them together.

A detail for perfectionists: stat_lock.wait_time changed type twice in one month — first to double precision, then a fix for precision loss in pg_stat_us_to_ms(), then a typo caught in the same function. Microseconds to milliseconds proved harder than it looks.

A cap on logged SQL

c8bd8387c27, Fujii Masao, July 3. A pain familiar to every DBA: an application sends an INSERT with a 40 MB literal, log_min_duration_statement is on, and the logs balloon.

SET log_statement_max_length = 1024;  -- bytes
--  0 — log an empty statement body
-- -1 — previous behaviour (the default)

Truncation is byte-based, but clips on multibyte character boundaries so the log never contains broken UTF-8.

Crime blotter

What got caught

  • Data corruption on day one: Fix unlogged sequence corruption after standby promotion, June 30.
  • A race in the heart of the buffer manager: bufmgr: Fix race in LockBufferForCleanup().
  • Visibility map without WAL: Melanie Plageman, a block of four commits — the VM was cleared without properly registering blocks in WAL. A direct route to divergence after recovery.
  • Isolation leak: Prevent access to other sessions' empty temp tables.
  • Crash from SQL: satisfies_hash_partition fell over on VARIADIC NULL.
  • A triple coincidence: RETURNING OLD plus a BEFORE trigger plus a concurrent update.
  • A stuck summarizer: Robert Haas — walsummarizer hung at a timeline switch.
  • Unicode: Jeff Davis — defences against truncated UTF-8, the final sigma, missing unsigned char casts.
  • An SSI race in nbtree: Peter Geoghegan, plus four commits of new coverage.

Stabilising PG 19 was the month's second-largest seam: sequence synchronization (13 commits, including a revert and a redo), online checksum enabling (7), REPACK CONCURRENTLY (6), FOR PORTION OF (6), property graph / SQL/PGQ (9), dynamic logical decoding (6).

Small things that please

min() and max() for uuid. The uuid type has long had a full set of comparison operators and a btree opclass — it is totally ordered. Only the aggregates were missing. uuid_larger() and uuid_smaller() fill the gap. A lovely detail from the commit message: values compare lexicographically across all 128 bits, and in UUIDv7 the high bits encode a Unix timestamp. So min() and max() over UUIDv7 genuinely return the oldest and newest values.

Index names for expression indexes became meaningful — two commits from Tom Lane. A small thing, wanted for years.

An MD5 warning. Password authentication against an MD5-hashed password now emits a warning. MD5 itself was not removed — but the hint could hardly be broader.

psql: the pg_read_all_stats role can finally see database size in \l+; tab completion for \df works for procedures; pager selection is fixed for wrapped expanded output.

pg_recvlogical sends a final feedback message on SIGINT/SIGTERM, so progress is no longer lost on a clean shutdown.

Prefix operators return. Commit 2f094e7ac made | and -> built-in operator names, correctly giving them precedence and adding infix productions — but forgot prefix ones. At least one extension relied on that. Bug #19558, reported by Pierre Senellart.

Syntax corners closed: set-returning functions are now disallowed inside OVER; renaming a rule to _RETURN is forbidden; io_min_workers exceeding io_max_workers now warns.
