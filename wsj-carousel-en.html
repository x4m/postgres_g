What PLAN actually does

How do you join rows coming from several NESTED PATH clauses? Until July the answer was hardcoded.

        ┌──────────────────────────────┐
        │  row pattern  '$'  AS root   │
        └──────────────┬───────────────┘
                       │  INNER / OUTER
       ┌───────────────┴───────────────┐
┌──────▼───────┐               ┌───────▼──────┐
│ NESTED       │  UNION/CROSS  │ NESTED       │
│ '$.phones'   │◄─────────────►│ '$.emails'   │
└──────────────┘               └──────────────┘
PLAN DEFAULT (INNER, CROSS)

Parent to child: INNER or OUTER.
Sibling to sibling: UNION or CROSS.

Fixable with refactoring. But the calendar said late beta.

The great cleanup

July took out
the trash.

  • Pre-v10 server support removed from pg_dump, pg_upgrade, psql
  • The refint extension deleted after six straight fix commits
  • Minimum toolchain raised to Visual Studio 2022 and ICU 55
  • pg_spin_delay(), getpgusername(), RADIUS in initdb — gone

VS 2019 died an interesting death: a commit swapped __builtin_types_compatible_p for C11 _Generic, and VS 2019 turned out to be, quoting the commit, "just broken for that."
