# Concurrency Testing Infrastructure: Comparison

## PostgreSQL proposals


|                                | Fault Injection Framework                                                        | POC: Stop Events                                                       | Injection Points (basic)                                                 | Injection Points: wait/wake                                                       |
| ------------------------------ | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| **Author**                     | Asim R P (Greenplum)                                                             | Alexander Korotkov                                                     | Michael Paquier                                                          | Michael Paquier                                                                   |
| **Date**                       | Aug 2019                                                                         | Nov 2020                                                               | Oct 2023                                                                 | Feb 2024                                                                          |
| **Origin**                     | Ported from Greenplum DB                                                         | Original PG proposal                                                   | Original PG proposal                                                     | Extension of the above                                                            |
| **Committed**                  | No                                                                               | No                                                                     | Yes (PG 17, `49cd2b93`)                                                  | Yes (PG 17, `9892a01d`)                                                           |
| **Mechanism**                  | Dedicated fault injector process, special connection string (`am_faultinjector`) | "Stop events" — shared memory flag checked at named points             | Named callback hooks in shared memory, loaded via extension              | Condition variable wait/wake on top of basic injection points                     |
| **Condition logic**            | SQL-controlled fault types per point                                             | JSONPath expression over JSONB parameters exposed by the point         | None — just fires a registered callback                                  | None — explicit `injection_points_wake(name)` call                                |
| **Synchronization**            | Remote process sends command to unblock                                          | Automatic — process stops until `pg_stopevent_reset()`                 | None in base; callback decides                                           | CV wait; `injection_points_wake()` broadcasts                                     |
| **Works in critical sections** | No                                                                               | No                                                                     | Callback can avoid blocking — yes if callback is simple                  | **No** — CV uses `WaitLatch` + `WL_EXIT_ON_PM_DEATH` + palloc chain               |
| **Works before shmem**         | No                                                                               | No                                                                     | No                                                                       | No                                                                                |
| **Test integration**           | Isolation tests + TAP                                                            | SQL functions in any test                                              | TAP (via psql + `injection_points` extension)                            | TAP; `wait_event_type='InjectionPoint'` in `pg_stat_activity`                     |
| **Runtime overhead (no-op)**   | Moderate — shm check every point                                                 | Moderate — shm check + JSONPath eval                                   | Very low — pointer check in shm                                          | Very low — same                                                                   |
| **Key strength**               | Rich fault types (error, sleep, panic, skip), well-tested in Greenplum           | Context-aware conditions via JSONPath; usable by non-backend processes | Minimal, extensible; compile-time optional (`--enable-injection-points`) | Deterministic process synchronization; first-class race condition testing         |
| **Key weakness**               | Too intrusive; `am_faultinjector` redesign needed; community pushback            | Complex JSONPath dependency; never completed                           | No synchronization — can't reliably test races                           | CV restriction: unusable in critical sections; kill -9 can cause spurious wakeups |

## Similar techniques in other systems


| System                   | Mechanism                                            | Notes                                                                                                                                                                                                                           |
| ------------------------ | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **MySQL / InnoDB**       | `DEBUG_SYNC` + `DBUG_EXECUTE_IF`                     | `DEBUG_SYNC` allows named sync points with `SIGNAL`/`WAIT_FOR`; `DBUG` can inject errors, sleep, print. Both compile-time (`-DWITH_DEBUG`). Widely used in MTR tests. Very similar to PG injection points + wait/wake combined. |
| **CockroachDB**          | `TestingKnobs` (Go interfaces)                       | Per-subsystem hook structs passed through code; tests inject callbacks before compile. Very powerful but tightly coupled to test code — not available in prod builds. Closer to Alexander Korotkov's approach in spirit.        |
| **TiDB**                 | `pingcap/failpoint`                                  | Port of FreeBSD kernel failpoints to Go. Failpoints are enabled/disabled at runtime via HTTP or env vars. Supports sleep, panic, return, print. Similar to MySQL DBUG but for Go.                                               |
| **FreeBSD kernel**       | `fail(9)` / `fail_point`                             | Original inspiration for most database fault injection. Named points with `fail_point_eval()`; controlled via `sysctl`. Supports sleep, return, panic, break, print.                                                            |
| **Linux kernel**         | fault-injection framework (`CONFIG_FAULT_INJECTION`) | Injects failures into `alloc_pages`, `kmalloc`, disk I/O. Probabilistic or nth-call triggering. Controlled via debugfs. No synchronization primitive — sleep-based only.                                                        |
| **FoundationDB**         | Deterministic simulation                             | Fundamentally different approach: entire runtime (network, disk, time) is simulated deterministically. Races are reproduced by replaying seeds. Most powerful but requires simulation-aware architecture from the start.        |
| **Cassandra / Java DBs** | Byteman                                              | JVM bytecode injection at runtime — can insert arbitrary code at any method entry/exit/line. Very powerful for JVM-based systems; no equivalent for C.                                                                          |
